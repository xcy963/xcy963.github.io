- 这里要介绍下`config.toml`的机制,把远程的源转化为本地的vendor
- 其实cargo有自带这个机制使用命令`cargo vendor --versioned-dirs ../third_party/cargo`就好
  - 他还会生成`.cargo/cargo.toml`文件的配置信息,帮助我们配置这些库

### 关于rust的offline模式

- 一般我们在项目根目录下的`Cargo.toml`文件中会指明相关的依赖,然后一般编译cargo会自已去构建,但是比赛方不允许
```toml
[package]
name = "user_lib"
version = "0.1.0"
authors = ["Yifan Wu <shinbokuow@163.com>"]
edition = "2018"

# See more keys and their definitions at https://doc.rust-lang.org/cargo/reference/manifest.html

[dependencies]
#比如这个地方就有好多
buddy_system_allocator = "0.6"
bitflags = "1.3.2"
spin = "0.9"
lock_api = "0.4.12"
lazy_static = { version = "1.4.0", features = ["spin_no_std"] }

[profile.release]
opt-level = "z" # Optimize for size.
lto = true
[profile.dev]
debug = 2
```

- 所以需要使用离线模式,一个简单的命令示范
  - 前面的`RUSTUP_OFFLINE`,`CARGO_NET_OFFLINE`,`RUSTC`,`RUSTDOC`是设置相关的环境变量
  - 最后的参数`--offline`确保不会联网,他会使用本地的库
```bash
RUSTUP_OFFLINE=1 CARGO_NET_OFFLINE=true RUSTC=/root/.rustup/toolchains/nightly-2025-01-18-x86_64-unknown-linux-gnu/bin/rustc RUSTDOC=/root/.rustup/toolchains/nightly-2025-01-18-x86_64-unknown-linux-gnu/bin/rustdoc /root/.rustup/toolchains/nightly-2025-01-18-x86_64-unknown-linux-gnu/bin/cargo build --release --offline ;\
```
- 前面编译有个前提是第三方库在本地有源码,但是没有怎么办?又要怎么指定源码的目录?

- 先看指定源码目录的方式
```toml
[build]
target = "riscv64gc-unknown-none-elf"

[target.riscv64gc-unknown-none-elf]
rustflags = [
    "-Clink-args=-Tsrc/linker.ld",
]

[source.crates-io]
#重定向写在这里
replace-with = "vendored-sources"

[source.vendored-sources]
#指明具体的目录
directory = "../third_party/cargo"

[net]
offline = true

```

- 如何获取库的源码?
  - 最简单的方式是先联网编译一遍,然后使用`cargo vendor third_party/cargo`
    - 这个目录是上面指明的目录
  - 也可以自己去找`.crate`文件,
