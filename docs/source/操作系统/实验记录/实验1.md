### 1. lss指令

```s
lss init_stack,%esp  

init_stack:                          # Will be used as user stack for task0.
	.long init_stack
	.word 0x10

```

```{hint}
lss是从init_stack读取出一个32bit值(long)还有一个16位值(word)
16位 给ss 32位 给后面约定的寄存器
```

- 在这个地方代码的运行结果就是段寄存器ss给到0x10 %esp给到0x0bd8(指向init_stack段的一个指针) 
- 这个地方的结果就是创建一个临时的GDT

```{note} 
为什么有两个lss?
因为第一次是设置临时GDT,(只有栈寄存器的段)保证两个函数能正常使用
第二次是因为设置GDT的时候把段寄存器改了
```

### 2. 在保护模式怎么寻址?

- 这里以寻找中断向量表为例子

```s
movw $timer_interrupt, %ax
movw $0x8E00, %dx

movl $0x08, %ecx              # The PC default timer int.要设置的中断
lea idt(,%ecx,8), %esi        # 我们需要设置中断向量0x08,之后两个任务的切换需要使用这个中断
movl %eax,(%esi)              # 这个是按地址寻址
movl %edx,4(%esi)             # 这个是地址向后加4个字节
```


```{tip}
这里还有对寄存器的使用技巧

```txt
movl $0x00080000, %eax	      # EAX[31:16] = 0x0008 寄存器也是高高低低的首地址对应低有效位
movw $timer_interrupt, %ax    # EAX[15:0] = offset_15..0 中断函数

```


### 3. 用户态tss放在哪里?如何从tss里面恢复和保存数据
```{note}
这里tss是每个用户程序都有一个,linux0.00比较简单,正常tss应该用队列进行维护

```


- 1. tss是放在GDT里面的
```s
gdt:	.quad 0x0000000000000000	/* NULL descriptor */
	.quad 0x00c09a00000007ff	/* 8Mb 0x08, base = 0x00000 */
	.quad 0x00c09200000007ff	/* 8Mb 0x10 */
	.quad 0x00c0920b80000002	/* screen 0x18 - for display */

	.word 0x0068, tss0, 0xe900, 0x0	# TSS0 descr 0x20
	.word 0x0040, ldt0, 0xe200, 0x0	# LDT0 descr 0x28
	.word 0x0068, tss1, 0xe900, 0x0	# TSS1 descr 0x30
	.word 0x0040, ldt1, 0xe200, 0x0	# LDT1 descr 0x38
end_gdt:
```

- 2. 介绍长跳转ljmp
```s
ljmp $TSS1_SEL, $0
```

```{note}
当cpu发现长跳转的段选择子是一个tss段(从GDT的描述符里面读出来的)的时候会先恢复数据再跳转(他认为是一个任务切换)
```

### 4. EFLAGS是什么?

```{note}
EFLAGS本身是一个寄存器,用来保存运算结果的各种状态,还有CPU 当前的一些控制状态。
几个例子

| 位     | 名字     | 作用（直白版）                                        |
| ----- | ------ | ---------------------------------------------- |
| 0     | CF     | Carry Flag：算术有进位/借位。比如加法溢出到高位。                 |
| 2     | PF     | Parity Flag：结果的最低 8 位 1 的个数是偶数吗。一般你用不到。        |
| 4     | AF     | Adjust Flag：BCD 用的，平时也很少手撸。                    |
| 6     | ZF     | Zero Flag：结果是不是 0。`cmp` 之后常用。                  |
| 7     | SF     | Sign Flag：结果最高位是不是 1（也就是正负号）。                  |
| 8     | TF     | Trap Flag：单步调试用，设 1 会每条指令都触发调试异常。              |
| 9     | **IF** | Interrupt Flag：**中断允许开关**。`sti` 置 1，`cli` 清 1。 |
| 10–11 | IOPL   | I/O 特权级，一般是内核控制，用户态不能随便改。                      |
| 12    | **NT** | Nested Task：任务嵌套标志，配合 TSS/任务切换用。               |
| 14    | RF     | Resume Flag：调试相关。                              |
| 17    | VM     | Virtual 8086 模式标志。                             |

```

- 如果想要对EFLAGS进行修改，我们需要

```s
pushfl
andl $0xffffbfff, (%esp) #对当前的栈的地址上面的数据进行操作
popfl
```
**输出的结果是bit14（NT 标志位）清 0**

```{tip}
NT 这个标志会影响 iret 在有 TSS 的时候的行为，所以进用户态前先把它关掉。
就是用户态有一个函数他的返回不能把我们的内核函数ret，否则执行一个用户程序之后我们的操作系统直接就关机了
```
