# 🛠️操作系统简单介绍

## 基本知识扫盲
### **1为什么寻址是cs::ip**

#### 1 为了支持多任务
-  每个任务(程序)有自己的代码段，数据段，栈段，任务切换时只需要切换段寄存器就行了

#### 2 早期16位寄存器只能表示64KB，但需要寻址1MB
> 当然现在为了兼容性，x86架构依然保留了这种寻址方式。流程上是实模式（16位）→ 保护模式（32位）→ 长模式（64位）


### **2对比传统bios启动还有uefi模式启动**
> 他还有个问题是磁盘只能支持2TB

```txt
// 传统bios启动
1. CPU复位 → 16位实模式
2. BIOS加载第一个扇区到0x7C00
3. 执行你的boot.s代码
4. 手动切换到保护模式(在boot.s中完成)
5. 加载内核
```

```txt
// UEFI启动
1. CPU复位 → 直接进入保护模式
2. UEFI固件初始化硬件
3. 查找EFI系统分区
4. 加载EFI应用程序（.efi文件）
5. 执行EFI应用程序（已处于保护模式）
```

### **3汇编执行顺序**
> 正常的汇编如果没有jump的话都是从start函数开始顺序,对应cpu就是不断取指执行

### **4寄存器简单介绍**
1. 通用寄存器`（AX / BX / CX / DX）`
- AX / EAX（累加器）accumulate 
- BX / EBX（基址寄存器）base
- CX / ECX（计数寄存器）count
- DX / EDX（数据寄存器）data

2. 段寄存器`（CS / DS / SS / ES / FS / GS）`
- CS（代码段寄存器）code segment
- DS（数据段寄存器）data segment
- SS（堆栈段寄存器）stack segment
- ES / FS / GS（附加段寄存器）extra segment 按字母顺序排的

3. 指针 / 索引寄存器`（SP / BP / SI / DI / IP/EIP）`
- SP / ESP（堆栈指针寄存器）stack pointer
- BP / EBP（基址指针寄存器）base pointer
- SI / ESI（源变址寄存器）source index
- DI / EDI（目的变址寄存器）destination index
- IP / EIP（指令指针寄存器）instruction pointer

4. FLAGS / EFLAGS（标志寄存器）
- ZF（零标志）Zero Flag
- CF（进位标志）Carry Flag
- SF（符号标志）Sign Flag   
- OF（溢出标志）Overflow Flag
- IF（中断标志）Interrupt Flag 由sti/cli 控制

### **5GDT/LDT**
> 就是一张“段描述符的表”，保护模式下 CS/DS 这些段寄存器不再是“段地址”，而是“表里的第几个格子”。
>
> GDT 是全局的表，LDT 是每个进程可以有一张自己的表。

1. **实模式：段寄存器 = 直接参与物理地址**

- 在实模式下，：

```text
物理地址 = 段寄存器 * 16 + 偏移
```
- `**eg1**`CS = 0x07C0, IP = 0x0000 → 物理地址 = 0x7C00（boot 扇区）
- `**eg2**`DS = 0x1000, SI = 0x0000 → 物理地址 = 0x10000（你加载 head 的地方）

2. **保护模式:保护模式：段寄存器不再是段基址，而是“索引”**
- CS / DS 等段寄存器里放的，不再是直接的段基址；
- 而是一个 **“段选择子（selector）”**，用这个 selector 去 **GDT/LDT 里查一个 8 字节的“段描述符”**；
- 描述符里才记录：**真正的基址、段大小、权限、是否 32 位、是否代码段/数据段……**
  
> 实模式：
> CS = 0x1000 ⇒ 就是段基址 0x10000 起
>
>保护模式：
>CS = 0x0008 ⇒ 表示“去 GDT 的第 1 项（索引 1）看看它描述的是什么段”，
>然后用那里面的 base/limit/flags 来解释地址。

3. **一个具体的GDT例子**
```txt
gdt:    .word   0,0,0,0     ! dummy（第0号描述符，必须全0）

        .word   0x07FF      ! 8Mb - limit=2047 (2048*4096=8Mb)
        .word   0x0000      ! base address=0x00000
        .word   0x9A00      ! code read/exec
        .word   0x00C0      ! granularity=4096, 386

        .word   0x07FF      ! 8Mb - limit=2047 (2048*4096=8Mb)
        .word   0x0000      ! base address=0x00000
        .word   0x9200      ! data read/write
        .word   0x00C0      ! granularity=4096, 386
```

GDT 里每个“段描述符”占 8 字节（4 个 word）。这里有：

- 第 0 项：`0,0,0,0` —— **空描述符**，规定必须存在，index=0 不用。
- 第 1 项：代码段描述符（你的内核代码段）
- 第 2 项：数据段描述符（你的内核数据段）

##### **分析一下这个GDT的第1项**
1. **base = 0x00000000**
   这一堆拆开组合就是“基址 0”。

2. **limit ≈ 8MB**

   * 低 16 位 limit：0x07FF
   * 高 4 位 limit：在最后一个 word 里（0x00C0 的高 4 bit 为 0）

   由于你设置了“粒度 = 4KB”（G=1），所以：

   ```text
   实际可用大小 ≈ (limit + 1) * 4KB ≈ (0x800) * 4KB = 0x800000 = 8MB
   ```

3. **属性 0x9A00 / 0x00C0：这是一个 32 位代码段**
- 下表是一个GDT段描述符的结构说明：
| 字节偏移 | 内容描述                  | 位范围        |
|----------|---------------------------|---------------|
| 0-1      | Limit 0..15（段界限低16位） | 15:0          |
| 2-3      | Base 0..15（基址低16位）   | 31:16         |
| 4        | Base 16..23（基址中8位）   | 39:32         |
| 5        | Access（类型/DPL/P等）     | 47:40         |
| 6        | Flags高4位 + Limit 16..19 | 51:48         |
| 7        | Base 24..31（基址高8位）   | 63:56         |

> 注意内存有小端存储,所以0x9A00在内存中是按00 9A存储的,所以access是9A base是00

- 0x9A → 二进制：1001 1010b
| 位   | 含义                               | 这里的值               |
| --- | -------------------------------- | ------------------ |
| 7   | P (Present)                      | 1 = 段存在            |
| 6–5 | DPL (Descriptor Privilege Level) | 00 = 特权级 0（内核）     |
| 4   | S (Descriptor type)              | 1 = 代码/数据段（而不是系统段） |
| 3–0 | Type（具体类型）                       | 1010b = 0xA        |

> 结论:段存在, 特权级0,代码段,可执行可读,未访问

- 0x00C0 → 二进制：1100 0000b
按 Intel 布局：

| 位   | 含义                         | 这里的值               |
| --- | -------------------------- | ------------------ |
| 7   | G (Granularity)            | 1 = 粒度 4KB         |
| 6   | D/B (Default operand size) | 1 = 32 位段          |
| 5   | L (64-bit code)            | 0 = 不是 64 位代码      |
| 4   | AVL（OS 自用）                 | 0                  |
| 3–0 | Limit 16..19               | 0000b = 高 4 位界限为 0 |

> 结论:粒度4KB,32位段,不是64位代码段

## 操作系统启动流程

> 1上电之后bios做完硬件检查就会把操作系统加载到0x7c00处 
> 2然后执行boot.s代码,这个代码的主要任务是把操作系统从实模式切换到保护模式,顺便把内核代码送到内存最低端
> 3执行内核代码head.s,这个代码主要是设置中断描述符表,任务状态段等保护模式下需要的东西,然后实现一个简单的多任务系统


## 阅读linux0.00源码
> **源码效果是不停打印A B**
>
> `boot.s`：把系统从“16 位 BIOS 的世界”带到“32 位保护模式世界”。
>
> `head.s`：在 32 位世界里，搭好中断 & 任务切换的骨架，然后跑两个小任务。
>
### 下面是简单的流程说明
1. 电脑上电后 → BIOS 运行 → 把硬盘第一个扇区（512 字节）读到内存 `0x7c00`，然后跳过去执行。

2. 这 512 字节里的就是你贴的 **`boot.s`**（引导扇区）。

3. `boot.s` 的工作大致是：

   * 先把自己搬到一个更安全的位置（`0x07c0:0000`）。
   * 用 BIOS 中断 `int 0x13` 从磁盘继续把“真正的系统”（也就是后面的代码，包括 `head.s` 等）加载到内存 `0x10000`。
   * 构造一个最简单的 GDT / IDT，**切换到 32 位保护模式**，然后跳到保护模式入口（就是 `head.s` 里的 `startup_32`）。

4. `head.s` 在已经是 32 位环境下运行，主要做几件事：

   * 正式设置好 **GDT 和 IDT**（中断描述符表）。
   * 初始化 8253 定时器芯片，让它定期产生时钟中断。
   * 设置定时器中断、系统调用中断的向量。
   * 设置两个 TSS、两个 LDT，构造一个非常简陋的 **双任务多任务系统**：

     * task0 不停打印 `A`
     * task1 不停打印 `B`
   * 利用时钟中断，在两个任务之间来回切换。

### **5关于cpu中断**
- 软件中断:通过int指令触发的中断,比如`int 0x13`是bios提供的磁盘服务中断,相当于调用函数
- 硬件中断:外设通过中断控制器发送的中断,这个需要cpu的中断标志位IF打开才行,通过`sti`指令打开,`cli`指令关闭
  - 打开之后如果cpu执行完当前的指令就会跳到中断向量表对应的地址执行
- 异常中断:cpu在执行过程中检测到错误自动触发的中断,比如除0错误,缺页错误等,相当于调用退出的函数


### boot.s源码注释
```s
! boot.s
! 简单 bootloader：
! 1. 从磁盘读取若干扇区作为“内核镜像”到内存 0x10000
! 2. 把内核搬到 0x00000
! 3. 设置 GDT/IDT，打开保护模式
! 4. 跳到保护模式下的内核入口（段选择子 8，偏移 0）

BOOTSEG = 0x07c0          ! BIOS 把 boot 扇区加载到物理 0x7C00。
                          ! 这里我们假定当前代码段 CS = 0x07C0，
                          ! 也就是 CS:IP = 07C0:0000 => 物理地址 0x7C00。

SYSSEG  = 0x1000          ! 后面从磁盘读出来的系统(内核)先加载到这里：
                          ! 段地址 0x1000 => 物理地址 0x1000 << 4 = 0x10000。

SYSLEN  = 17              ! 要读取的扇区数：17 个扇区 => 17 * 512 = 8704 字节。

entry start               ! 程序入口标签 start
start:
    jmpi go,#BOOTSEG      ! 远跳转：CS := BOOTSEG(0x07C0), IP := go 的偏移。
                          ! 这样我们确定后续执行环境里 CS = 0x07C0。

go:
    mov ax,cs             ! AX = 当前 CS = 0x07C0。
    mov ds,ax             ! DS = 0x07C0（数据段与代码段一致，方便寻址）
    mov ss,ax             ! SS = 0x07C0（栈段也设为同一段）
    mov sp,#0x400         ! SP = 0x0400，栈顶在 0x07C0:0x0400 处。
                          ! 这里只是随便找了一块栈空间（> 512 即不压到引导扇区就行,不然我们这个程序就会被破坏）。
                          !说明:使用ax的原因是cs不能直接mov到ss,ds

!-----------------------------------------------------------------------------
! 从磁盘读取“系统/内核”到 0x1000:0x0000（物理 0x10000）
!-----------------------------------------------------------------------------

load_system:
    mov dx,#0x0000        ! DX = 0
                          ! DH = 磁头号 head = 0
                          ! DL = 驱动器号 drive = 0（一般是第一个软盘/启动盘）

    mov cx,#0x0002        ! CX = 0x0002
                          ! CH = 柱面 cylinder = 0
                          ! CL = 起始扇区 sector = 2
                          ! 说明：我们从 0 面、0 柱面、2 号扇区开始读，
                          ! 也就是紧挨着引导扇区后面的那块区域。

    mov ax,#SYSSEG        ! AX = 0x1000
    mov es,ax             ! ES = 0x1000，这就是读入数据的目标段。
    xor bx,bx             ! BX = 0
                          ! 所以 ES:BX = 0x1000:0x0000 = 物理 0x10000。

    mov ax,#0x200+SYSLEN  ! AH = 0x02（BIOS 磁盘读扇区功能号）
                          ! AL = SYSLEN = 17（要读 17 个扇区）

    int 0x13              ! 调用 BIOS 磁盘中断：这个好像是退化成函数调用的中断
                          ! 从 0/0/2 开始连续读 17 个扇区
                          ! 放到内存 ES:BX = 0x1000:0x0000（0x10000）
                          ! 其实也就是在读取head.s代码部分到内存
                        
    jnc ok_load           ! 如果 CF = 0（没有出错），跳到 ok_load

die:                      ! 如果出错，就在这里死循环
    jmp die               ! 简单粗暴：一直跳自己，系统就卡死在这。

!-----------------------------------------------------------------------------
! 扇区已经读进来，现在开始准备切换到保护模式
! 步骤：
! 1. 先把从 0x10000 读到的内核搬到 0x00000
! 2. 设置 IDT/GDT
! 3. 打开 PE 位，切换到保护模式
! 4. 用远跳转进 32 位代码
!-----------------------------------------------------------------------------

ok_load:
    cli                   ! 清中断：关中断，防止切模式过程中被打断

    mov ax, #SYSSEG       ! AX = 0x1000
    mov ds, ax            ! DS = 0x1000（源数据段：刚刚读入内核的地方）

    xor ax, ax
    mov es, ax            ! ES = 0x0000（目标数据段：准备把内核搬到 0x00000）

    mov cx, #0x2000       ! 拷贝的字数（word），而不是字节。
                          ! 0x2000 word = 0x2000 * 2 = 0x4000 字节 = 16KB。
                          ! 也就是说从 0x10000 把 16KB 搬到 0x00000。,这个是为了把bios还有我们的boot.s覆盖掉,不然内存太浪费了

    sub si,si             ! SI = 0（源偏移）
    sub di,di             ! DI = 0（目标偏移）

    rep                   ! 重复前缀：重复执行 movw，直到 CX = 0
    movw                  ! 拷贝一个 word： [ES:DI] = [DS:SI]，然后 SI/DI/CX 自增/自减。

                          ! 简单理解：memcpy(0x00000, 0x10000, 16KB)

    mov ax, #BOOTSEG      
    mov ds, ax            ! DS = BOOTSEG = 0x07C0（恢复成 boot 段，后面要访问 gdt 等数据）

    lidt idt_48           ! 加载 IDT 寄存器：
                          ! IDTR.limit = 0
                          ! IDTR.base  = 0 (下面 idt_48 定义中说明)
                          ! 即当前 IDT 是空的，所有中断都会触发异常，
                          ! 但我们已经关中断(cli)，所以暂时没关系。

    lgdt gdt_48           ! 加载 GDT 寄存器：
                          ! GDTR.limit = 0x7FF
                          ! GDTR.base  = (0x7C00 + gdt) 这个地址
                          ! 也就是告诉 CPU：GDT 在内存 0x7C00 附近的 gdt 处，
                          ! 长度可以容纳 256 个描述符左右。

!-----------------------------------------------------------------------------
! 打开保护模式
!-----------------------------------------------------------------------------

    mov ax,#0x0001        ! AX = 1 => bit0 = 1
                          ! 在 CR0 中 bit0 是 PE（保护模式使能位）

    lmsw ax               ! 把 AX 的低 4 位加载到 CR0（早期 386 用法）
                          ! 等价于：CR0.PE = 1，打开保护模式

    jmpi 0,8              ! 关键一步：在保护模式下做一次远跳转
                          ! CS := 8（段选择子 = 1 号 GDT 描述符 * 8）
                          ! EIP := 0
                          ! 也就是跳到 GDT 中代码段描述符（索引 1）指定的
                          ! 基地址 + 偏移 0。
                          !
                          ! 这就是你的 32 位内核的入口地址：线性地址 0x00000000。

!-----------------------------------------------------------------------------
! GDT/IDT 描述符区
!-----------------------------------------------------------------------------

gdt:  .word   0,0,0,0     ! 第 0 号描述符：全 0，空描述符，必须保留不用。

        !------------------- 代码段描述符（索引 1，对应选择子 0x08）-------------------
        .word   0x07FF    ! limit 0..15：限制 = 0x07FF。
                           ! 开启 4KB 粒度后，实际限制 = (0x07FF << 12) + 0xFFF
                           ! 约等于 8MB 空间。

        .word   0x0000    ! base 0..15：基址低 16 位 = 0x0000

        .word   0x9A00    ! base 16..23 在高字节，低字节是属性：
                           ! 高字节：base 16..23 = 0x00
                           ! 低字节：0x9A
                           !   1 0 0 1 1010b：
                           !   P=1(存在)，DPL=00，S=1(代码/数据段)，
                           !   Type=1010(可执行/可读，未访问)

        .word   0x00C0    ! 高 4 位：limit 16..19 = 0
                           ! 低 4 位：标志 + base 24..31
                           !   1100b => G=1(粒度4KB), D=1(32位段), 其它 0，
                           ! base 24..31 = 0x00
                           ! => 基址为 0x00000000，limit ≈ 8MB，32 位代码段

        !------------------- 数据段描述符（索引 2，对应选择子 0x10）-------------------
        .word   0x07FF    ! 同样的 limit，8MB

        .word   0x0000    ! base 0..15 = 0x0000

        .word   0x9200    ! base 16..23 = 0x00
                           ! 属性低字节 0x92：
                           ! P=1, DPL=00, S=1(代码/数据段),
                           ! Type=0010(数据段，可读写)

        .word   0x00C0    ! 同样 G=1, D=1, base 24..31 = 0x00
                           ! => 基址 0，32位数据段，覆盖 0~8MB。

!-----------------------------------------------------------------------------
! IDT 和 GDT 的 48 位“指针”（用于 lidt/lgdt）
!-----------------------------------------------------------------------------

idt_48: .word  0          ! IDT limit = 0（长度为 0）
        .word  0,0        ! IDT base = 0x00000000（基址 0）

gdt_48: .word  0x7ff      ! GDT limit = 0x7FF（大小 2048 字节）
        .word  0x7c00+gdt,0
                          ! GDT base = 0x7C00 + gdt
                          ! 也就是当前这份 bootloader 中 gdt 表在内存中的物理地址

.org 510                  ! 填充到第 510 字节（0~509）
    .word   0xAA55        ! 最后两个字节写入 0xAA55，引导扇区签名。
                          ! BIOS 会检查这个签名才能把该扇区当成可引导扇区。


```
